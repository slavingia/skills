# Gotchas — validate-idea

Failure modes discovered through real usage. Read before every run.

## Validation Theater

**"Validation" by asking friends if the idea is cool — friends lie to be nice.**
They want to support you. They'll say "that's awesome!" to anything. Real validation requires strangers with the problem reaching for their wallet.

## Building Before Validating

**Most founders spend months building what nobody wants.**
The instinct is to code first and ask questions later. Resist it. A manual service, a landing page with a payment button, or a pre-sale email gets you signal faster than a prototype.

## Can't Name 10 Specific People

**If you can't name 10 specific people with the problem, the problem isn't real enough.**
Not "marketers" — name them. If you can't find 10 people to talk to, you don't have enough proximity to the problem to solve it.

## Problem vs. Solution Validation

**Confusing solution validation with problem validation — validate the PROBLEM first.**
"Would you use an app that does X?" tests your solution. "How do you currently handle X? What's painful about it?" tests the problem. Always start with the problem.

## No Existing Workarounds = Weak Signal

**Nobody currently trying to solve this problem = red flag, not green.**
If nobody has a workaround — not even a messy spreadsheet or manual process — the problem probably isn't painful enough to pay for. Existing hacky solutions are the strongest signal that demand exists.

## Competitor Search Blind Spots

**Exa `company_research_exa` returns funded startups — also check indie/bootstrapped alternatives on ProductHunt, IndieHackers.**
VC-funded companies show up in company databases. The real competitive landscape includes solo founders, open-source tools, and community-built solutions that don't appear in startup databases. Search ProductHunt, IndieHackers, and relevant subreddits.

## Domain Availability Trap

**Domain availability is not idea validation — a great .com means nothing without paying customers.**
Checking domains feels productive but tests nothing about demand. Don't let a perfect domain name create false confidence. Don't let an unavailable domain kill a validated idea.
