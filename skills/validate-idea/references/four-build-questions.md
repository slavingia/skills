# Four Questions to Ask Before Building

From *The Minimalist Entrepreneur* by Sahil Lavingia. All four must be "yes" before writing code.

## 1. Can I ship it in the span of a weekend?

The first iteration should be prototyped in 2-3 days. Not a polished product — a functional thing that solves the core problem.

**Why it matters:** If the MVP takes months, you're over-engineering. Scope down until a weekend is realistic. What's the smallest thing that delivers value?

**Examples:**
- A Typeform + Zapier + Google Sheets workflow instead of a custom app
- A Carrd landing page with Stripe checkout instead of a full e-commerce site
- A concierge service where you do it manually, tracked in a spreadsheet

**Red flag:** "I need to build X, Y, and Z before anyone can use it." You don't. Ship the smallest slice.

**Green flag:** "I could set this up with existing tools this weekend and start taking orders."

## 2. Is it making my customers' lives a little better?

That's a minimum viable product — emphasis on *viable*. It doesn't need to be transformative. A little better is enough to start.

**Why it matters:** Perfection is the enemy of validation. If it saves someone 20 minutes a week, that's real value. You don't need to 10x their workflow on day one.

**Examples:**
- Saves 30 minutes of manual work per week
- Reduces a 5-step process to 2 steps
- Puts information in one place instead of scattered across 3 tools

**Red flag:** "It's cool but I don't know if anyone actually needs it." Cool is not a business.

**Green flag:** "My test users keep asking when they can use it again."

## 3. Is a customer willing to pay me for it?

Profitable from day one. Not "will pay eventually" — will pay now, for the current version.

**Why it matters:** Free users tell you nothing about willingness to pay. A customer who pays $10/month for your janky v1 is worth more signal than 1,000 free signups.

**Examples:**
- Pre-sold 5 annual subscriptions before building
- Charged for the manual service and customers didn't blink
- Set up a "buy now" button and 3 people clicked it in the first week

**Red flag:** "I'll monetize later once I have enough users." Later never comes. If people won't pay for it now, adding features won't change that.

**Green flag:** "Someone already Venmo'd me for doing this manually."

## 4. Can I get feedback quickly?

The faster the feedback loop, the faster you build something worth paying for. You need a tight cycle: ship, observe, learn, adjust.

**Why it matters:** Building in isolation for months produces exactly what you imagined, not what customers need. Weekly (or daily) feedback from real users keeps you honest.

**Examples:**
- Direct Slack/WhatsApp channel with first 10 users
- Weekly 15-minute calls with 2-3 customers
- Usage analytics that show what features people actually use

**Red flag:** "I'll launch in 6 months and see how it goes." Six months of guessing is six months of waste.

**Green flag:** "I shipped a change yesterday and heard back from a user by lunch."

---

## Scoring Framework

| Question | Yes | No |
|----------|-----|----|
| Ship in a weekend? | Scope is realistic, proceed | Scope down ruthlessly until this is yes |
| Making lives better? | Real value identified | Find the pain point or pivot |
| Will they pay? | Demand validated | Test pricing NOW before building more |
| Quick feedback? | Learning loop exists | Set up a direct channel with users first |

**All four "yes"** = Build it. You have a validated, scoped, monetizable idea with a feedback loop.

**3 of 4** = Fix the gap before proceeding. The missing piece will bite you.

**2 or fewer** = Go back to Step 1 (Define the Problem). You're likely solving a problem that isn't painful enough, for people you don't have access to, at a scope that's too large.
